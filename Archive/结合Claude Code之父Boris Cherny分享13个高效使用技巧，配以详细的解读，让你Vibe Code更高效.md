之前网络上Boris Cherny分享13个高效使用技巧传的沸沸扬扬，我结合我近期开发的一些经验，再详细解读一下这些技巧，让你在开发中更加的事半功倍。

具体如下：

1、尽可能并行

### 原文：在终端中同时运行5个Claude实例。将标签页编号为1-5，并通过系统通知来获知哪个Claude需要输入指令

### 解读： 刚接触智能编程的开发人员，在开始的阶段总是对其编码的能力半信半疑，所以总是盯着智能编程器干活，生怕出现什么幺蛾子。但是现在智能编程的能力已经比肩资深开发者。所以对于这种开发者，我们需要完全的信任，并且这种开发者越多越好，所以我们的应该运行更多的实例，并行开发。这样能将工作效率最大化。缺点只有一个。TOKEN的账单会节节攀升。

### 2、网页和本地同时并行

### 原文：同时在 http://claude.ai/code 上运行5-10个Claude实例，与本地Claude并行工作。在终端编程时，我经常将本地会话转至网页端（使用&符号），或在Chrome中手动启动新会话，有时还会用–teleport参数在两端来回切换。每天早晨和白天工作中，我会用手机（通过Claude iOS应用）开启几个会话，稍后再来查看进度。

### 解读： 现在智能编程的能力已经很强了，所以别像辅导实习生那样盯着它，把注意力放在更有价值的事情上。让智能编程软件在远程开发。

### 3、一个诸葛亮顶三个臭皮匠

原文：所有任务都使用支持深度思考的Opus 4.5模型。这是我用过最好的编程模型——虽然比Sonnet版本更大、响应稍慢，但由于它几乎很少需要人工引导且具备更出色的工具调用能力，实际使用效率比小型模型更高。

解读：很多开发任务，使用贵的模型一次就能跑通，但是使用免费或者便宜的模型，模型总是卡在某个功能的实现上反复开发测试。仿佛遇到问题时百思不得其解的我们。

4、不要再一个地方摔倒两次

原文：我们团队共享一个为Claude Code代码库设置的http://CLAUDE.md 文件。并将其 check in 到git中，全体成员每周都会进行多次协作更新。每当发现Claude出现操作偏差，我们就会将其记录到 http://CLAUDE.md 中，这样Claude下次就能规避同样问题。其他团队也维护着各自的 http://CLAUDE.md 文件，及时更新内容已成为各团队的基本职责。

解读：开发经验很重要，对于我们是如此，对于模型也是如此，因为CLAUDE.md 会作为上下文输入到智能体中，这样它在开发的时候就能避免之前犯过的错误。

5、让模型学会我们的经验

原文：在代码审查时，我经常在同事的PR中标记@.claude，把需要补充到http://CLAUDE.md的内容作为PR的一部分。我们为此专门使用Claude Code的Github Action（通过/install-github-action安装）。这相当于我们团队对@danshipper提出的“复利式工程”（Compounding Engineering）。

解读：很多人将智能编程比喻为抽卡，这是因为智能体没有认识到我们真正想要的是什么，而让其开发出我们真正想要的东西，我们需要将自己的真实需求尽可能详细的当成上下文给到智能体。

6、计划先行

原文：大多数会话都从规划模式开始（Plan mode，按两次shift+tab键）。如果我的目标是编写一份Pull Request，就会使用规划模式，与Claude反复沟通直到对方案满意。随后切换到自动接受编辑模式（auto-accept edits mode），Claude通常能一次搞定。一个优质的规划至关重要！

解读：以往的开发阶段是渐进式，这是由于开发人员的精力有限，总是将有价值的功能优先开发，例如敏捷开发。这种走一步看一步的开发方式在当今无疑是一种弊端，这是因为我们使用智能编程软件开发的时候，智能体会将我们之前开发的代码当成上下文。在开发新功能的时候无疑变成了一种无形的约束。所以在当今人工智能如此强大的时候，我们应该将更多的时间花在计划上，完善产品需求文档上，如果这很难，我们可以跟人工智能对话，让其帮助我们完善产品需求。这样你会发现使用完善的产品需求文档开发出来的产品会比渐进式提需求开发出来的产品无论在架构上还是功能实现上都优秀很多。

7、将固定的工作打包成工作流

原文：对于每天要重复多次的“内循环”（inner loop）工作流，我全部使用斜杠命令实现。这让我免于重复编写提示词，也让Claude能调用这些工作流。这些命令都通过git管理，存放在.claude/commands/目录中。例如，我和Claude每天会使用几十次/commit-push-pr斜杠命令——该命令通过内联bash预计算git状态等信息实现快速执行，避免与模型来回沟通的耗时。https://code.claude.com/docs/en/slash-commands#bash-command-execution

解读：之前一些固定的工作流使用脚本实现，如果可以让智能体帮我们实现和调用。

8、将固定的工作打包成智能体

原文：我经常使用几个子智能体：code-simplifier在Claude完成任务后对代码进行简化，verify-app包含端到端测试Claude Code的详细指令等。与斜杠命令类似，我认为子智能体能自动化处理我为大多数PR执行的最常见工作流。https://code.claude.com/docs/en/sub-agents

解读：使用子智能体代替我们完成一些常规的、固定的工作。

9、将固定的工作打包成智能体

原文：我们用PostToolUse钩子函数格式化Claude生成的代码。Claude通常能直接输出格式规范的代码，钩子会处理剩下的10%细节，避免后续CI（持续集成）流程中出现格式错误。

10、权限管理

### 原文：我不使用–dangerously-skip-permissions参数，而是用/permissions命令预先授权环境中确认安全的常用bash命令，避免不必要的权限提示。这些设置大多保存在.claude/settings.json文件中并与团队共享。

11、将Claude Code当成智能助理使用

### 原文：Claude Code能帮我调用所有工具：我经常通过MCP服务器搜索并发布Slack消息、运行BigQuery查询分析数据（使用bq命令行工具）、从Sentry获取错误日志等。我们的Slack MCP配置已存入.mcp.json文件供团队共享使用。

解读：如果将Claude Code仅仅当成开发软件来用，显然没有完全发挥其用处，我们可以将其看成是通用的智能体，借助SKILL，让其帮我们处理更多的工作。

12、长任务的技巧

原文：针对耗时较长的任务，我会采取以下方式之一：

- (a) 要求Claude在完成后通过后台代理自行验证工作结果；
- (b) 使用一个代理 `Stop` 钩子，用更确定地方式执行验证；
- (c) 使用ralph-wiggum插件。

同时我还会在沙箱环境中使用–permission-mode=dontAsk或–dangerously-skip-permissions参数，避免会话中的权限提示阻断Claude的连续工作流程。

13、反馈的重要性

原文：最后一个小窍门：要让Claude Code产出卓越成果，最关键的一点或许是——为Claude建立工作验证机制。当Claude拥有这种反馈循环时，最终结果的质量能提升2-3倍。

比如我每次向http://claude.ai/code提交改动时，Claude都会通过Chrome扩展进行全流程测试：自动打开浏览器、检测用户界面，持续迭代直到代码运行无误且用户体验流畅。

验证机制因领域而异——可能是简单的bash命令执行，或是完整的测试套件运行，或是浏览器/手机模拟器中的应用程序测试。请务必投入精力打造坚实可靠的验证体系。

解读：让智能体看见自己的开发输出结果很重要。这有助于其更好地定位问题和改进开发代码。
