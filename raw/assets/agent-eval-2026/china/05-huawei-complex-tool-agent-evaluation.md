## 为什么值得阅读

这是本组资料中最贴近国内企业产品实施的官方文档，重点展示如何在 AgentArts 中围绕复杂工具调用任务准备数据集、选择评估器、运行评测并查看结果，补足纯论文对产品工作流描述不足的问题。

## 主要内容中文译介

文档面向需要多步工具选择与参数生成的 Agent。评测不是只判断最终回答文本，而是围绕完整工具调用链检查 Agent 是否选择正确工具、生成符合 Schema 的参数、保持合理的步骤顺序，并利用工具返回形成最终答案。

典型操作流程包括准备被测 Agent 和评测数据、配置评估任务、选择或组合评估器、运行批量评测，并在结果页面查看指标和单条样本详情。对于复杂任务，平台需要组合多个评估器覆盖不同维度，而不是用一个总分替代所有质量判断。

文档体现了产品化 Agent Eval 的基本形态：评测数据、Agent 版本、评估器和运行任务成为可管理对象；离线批量评估用于版本比较，在线评估则面向真实运行数据持续观察质量。

## 方法与评估设计

- **评测对象**：复杂工具调用 Agent 与多步执行轨迹。
- **核心维度**：工具选择、参数准确/Schema 合规、调用顺序、轨迹质量和最终结果。
- **评估方式**：按任务配置多个评估器，汇总指标并下钻样本详情。
- **运行形态**：离线数据集评测与在线运行质量观察。
- **产品流程**：数据准备 → 评估配置 → 批量运行 → 结果分析 → 版本优化。

## 对企业级平台的启示

1. 产品应提供面向非算法用户的评测向导，降低数据集、Agent 版本和评估器绑定成本。
2. 工具调用应有专用可视化和分项指标，展示工具名、参数、返回、顺序、错误和重试。
3. 离线与在线评估应复用同一评估器定义，避免开发与生产口径分裂。
4. 企业平台需要评估器组合、阈值、权重和适用场景管理，并保留版本与修改审计。
5. 国内产品选型时应实测其自定义评估器、Trace 导出、私有化、多租户、成本和第三方 Agent 接入能力。
6. 对工具 Schema 的确定性校验应优先使用规则/代码，不应全部交给模型 Judge。
