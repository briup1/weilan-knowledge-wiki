# OpenAI：内部数据 Agent 的建设与持续评估

- 原文标题：Inside OpenAI’s in-house data agent
- 发布机构：OpenAI

- 原文链接：https://openai.com/index/inside-our-in-house-data-agent/

## 为什么值得阅读

这是少见的企业内部 Agent 真实案例：评测不是展示 Demo 的附属品，而是保护持续演进系统可信度的“单元测试与生产金丝雀”。文章还把企业语义上下文、数据权限、可验证结果和评测闭环放在同一架构中讨论。

## 主要内容中文译介

OpenAI 的内部数据 Agent 服务于公司数据平台，帮助员工发现数据、生成和执行 SQL、完成分析并发布结果。它通过表结构、血缘、历史查询、人工注释、代码语义、组织知识和运行时查询等多层上下文理解企业数据；记忆能力既可沉淀全局知识，也可保留个人纠正。

随着 Agent 持续上线和变化，质量同样可能持续漂移。团队使用 Evals API 构建系统化评估：每个测试以一个重要分析问题为输入，并配套由人工编写的 Golden SQL。评测运行时，让 Agent 生成查询、执行 SQL，再将生成 SQL 和实际结果与 Golden SQL 的执行结果共同比较。由于不同 SQL 可能语法不同但语义等价，评分不能依赖简单字符串匹配；评估器要容纳无害差异，并输出分数和解释。

这批评测在开发过程中持续执行，用于发现回归，也作为生产系统中的金丝雀。文章同时强调结果可验证性：用户可以查看 Agent 的假设和执行步骤，并直接进入底层查询结果检查证据。安全方面，Agent 继承既有访问控制，只允许用户查询其原本有权限的数据。

## 方法与评估设计

- **测试输入**：覆盖重要业务指标和常见分析模式的自然语言问题。
- **Ground Truth**：人工编写的 Golden SQL 及其执行结果。
- **被测流程**：问题理解、上下文检索、SQL 生成、查询执行和结果解释。
- **评分信号**：SQL 结构、执行结果、可接受的等价变化和评估器解释。
- **运行方式**：开发期持续回归，并在生产中承担早期告警作用。
- **安全约束**：评测环境和 Agent 均应继承企业数据权限，保留可核验的执行证据。

## 对企业级平台的启示

1. 企业评测任务应绑定可执行的 Ground Truth，而不是只保存标准文本答案。
2. 对数据、搜索和分析 Agent，应分层定位失败：上下文/数据集选择、查询或工具生成、执行结果、最终解释。
3. Golden SQL、执行数据状态、评估器版本和 Agent 版本必须共同版本化，避免基准漂移后无法解释分数变化。
4. 平台要提供证据下钻：从总分进入生成查询、原始结果、假设和评分理由。
5. 线上用户纠正和真实失败应经过脱敏、审核后转化为回归题，形成持续扩展的评测集。
6. 权限评测必须使用真实授权语义，验证越权拒绝、替代数据选择和审计记录。

## 局限与阅读警告

文章介绍的是 OpenAI 内部专用数据 Agent，不是可直接购买的产品，也没有公开完整评测集、阈值和对照结果。正文明确描述 Golden SQL 和结果比较，但未提供跨时间数据快照的具体实现，企业落地时仍需自行建设可复现的数据版本机制。
