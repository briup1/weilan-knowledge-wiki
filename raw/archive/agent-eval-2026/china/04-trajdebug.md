# TRAJDEBUG：定位 Agent 失败轨迹中的最早关键错误

## 资料信息

- 原文标题：TRAJDEBUG: Can LLM Agents Diagnose Their Own Failures?
- 作者机构：清华大学、腾讯混元等
- arXiv 首次提交：2026-08-06
- 原文链接：https://arxiv.org/abs/2608.06346
- 资料类型：国内团队研究论文 / 轨迹诊断 Benchmark

## 为什么值得阅读

企业平台不仅要知道“失败了”，还要找到最早导致失败的关键步骤，并区分错误被后续修复还是持续传播。TRAJDEBUG 给出了多粒度轨迹历史、最早关键错误识别和传播分析的具体研究基线。

## 主要内容中文译介

长程 Agent 轨迹包含大量动作、工具观察和中间状态。最终失败可能由早期错误选择触发，也可能是局部错误被后续纠正后又出现新的问题。简单检查最后一步或要求模型解释失败，容易把症状当根因。

TRAJDEBUG 将轨迹诊断定义为识别**最早关键错误**：如果修复这一点，后续轨迹就可能恢复。方法将历史压缩成多个粒度，使诊断模型既能看到全局任务进展，也能在可疑区段查看细节；随后追踪错误是在后续被修复、被放大还是持续传播。

配套 TrajErrBench 包含 486 条人工标注失败轨迹，为错误定位和解释提供 Ground Truth。研究比较不同模型在自我诊断和跨模型诊断上的表现，说明生成能力强并不自动意味着能可靠定位自身失败。

## 方法与评估设计

- **核心任务**：在长程失败轨迹中定位最早关键错误步骤并解释原因。
- **数据集**：TrajErrBench，486 条人工标注失败轨迹。
- **上下文策略**：多粒度历史压缩，在全局概览与局部细节之间切换。
- **传播分析**：判断错误是否被修复、持续存在或引发后续连锁失败。
- **评估输出**：错误位置、错误类型、根因说明及与人工标注的一致性。

## 对企业级平台的启示

1. BadCase 页面应支持时间线、步骤聚类、错误传播图和“首个关键错误”标注。
2. Finding 数据模型要区分根因、症状、后续影响和是否自动恢复。
3. 长轨迹不能全部直接塞给 Judge；平台需提供摘要、窗口选择和关键事件索引。
4. 自动根因建议必须引用具体 Step、工具响应和状态证据，不能只生成泛化解释。
5. 人工诊断结果可沉淀为根因 Golden Set，用来评测和校准诊断 Agent。
6. 可将失败定位连接到责任组件：模型、提示词、工具、数据、环境、权限或评估器本身。

## 局限与阅读警告

486 条轨迹仍是有限规模，错误类型和 Agent 框架覆盖可能不足；“最早关键错误”在多因一果、并发调用或环境故障中也未必唯一。自动诊断适合提高排查效率，不应在高风险事故中替代工程师对原始证据的复核。
