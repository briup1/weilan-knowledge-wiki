# Agent 上下文：把 token 当有限资源来经营

---

## 一个让 Agent 突然变傻的故事

- 工具返回 4000+ token 的全量 JSON
- 关键用户诉求被挤出上下文窗口
- 根因：没把上下文当成有限资源来经营

<!-- 3 min -->

---

## 今天三个带走

1. 画出 Agent 上下文四层剖面图
2. 知道静态前缀、轨迹、动态提示词、状态栏分别怎么优化
3. 设计一个 2 周内可验证的压缩或记忆实验

<!-- 2 min -->

---

## 上下文剖面图

- 四层结构：静态前缀 → 轨迹 → 动态提示词 → 状态栏
- 静态前缀最大最稳定，轨迹最容易膨胀
- 优化本质：在有限 token 预算里放最相关的信息

<!-- 12 min -->

---

## 静态前缀优化

- System Prompt：角色、约束、格式、示例四要素
- Skill/Tool Prompt：触发时机、参数含义、边界条件
- 反模式：避免为「查订单」「查物流」各写一个定制工具

<!-- 10 min -->

---

## 轨迹与工具输出压缩

- 压缩对象：过时推理、 oversized tool_result、重复说明
- 压缩时机：单轮内即时压缩，跨轮达阈值时总结
- 大数据处理：提取、指向、分段

<!-- 12 min -->

---

## 记忆设计

- 三层记忆：工作记忆、Episodic 记忆、语义记忆
- 工作记忆进状态栏，长期记忆按需检索注入动态提示词
- 先检索再决定放什么，不要把全部记忆塞进 prompt

<!-- 10 min -->

---

## 收束与落地 CTA

- 一句话：上下文 = 固定前缀 + 历史轨迹 + 动态注入 + 当前状态
- 带走清单：画剖面 → 找最大消耗项 → 设计 2 周实验
- 示例：查订单工具返回从全量 JSON 改为 5 个关键字段
