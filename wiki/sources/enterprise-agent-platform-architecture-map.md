# 第4章 全书地图：平台参考架构与阅读路径

## 摘要

本文是《企业级 Agent 平台工程》第 4 章，提供全书的**阅读坐标**而非产品蓝图：把前三章的概念判断收束为「四层参考架构 + 八个能力簇」的共同地图。它回答「一个平台问题发生在哪一层、依赖哪些前置能力、应看哪些章节」，并给出以 DataAgent 为主线的端到端任务链路、一年建设路线（技术/治理/组织三条线）、按角色跳读的取舍路径。核心立场：企业 Agent 平台应按工程依赖关系展开（模型→数据/知识→Agent 能力→主线场景→生产化与治理），检验尺度是能力可复用、证据可追踪、失败可恢复、责任可确认、成本可解释。

## 核心要点

- **四层参考架构**：业务任务层（用 Agent 完成什么任务，Part VI/XI）、Agent 能力层（任务状态/工具调用/规划/长任务/多 Agent/协议，Part V）、智能与数据层（模型推理/结构化输出/RAG/语义层/湖仓/指标口径，Part II-IV）、基础设施与治理层（部署/网关/可观测/评估/成本/安全/合规/组织，Part VII-X）。层间有依赖顺序，上层不能绕过下层能力。
- **八个能力簇三分法**：
  - 执行骨架：Runtime（任务创建/推进/暂停/恢复/终止）、Registry（工具/Agent/能力/版本统一管理）、Policy（权限/脱敏/审批/安全边界执行）；
  - 智能放大器：Planner（决定下一步）、Memory（会话状态/长期偏好/任务上下文）、RAG/Knowledge（文档/元数据/知识进入 Agent）；
  - 反馈系统：Observability（trace/日志/指标/会话回放）、Eval（判断版本变好变坏）。
- **DataAgent 主线**：DataAgent 几乎天然穿过全部层级——模型层（规划/生成 SQL）、数据层（语义层/口径/湖仓）、知识层（元数据/历史分析）、Agent 层（Runtime/工具/Planner/人工介入）、治理层（权限/trace/评估/审计）、前端层（图表/引用/工作台）。一次请求经过任务创建→上下文加载→路径规划→工具执行→结果解释→治理记录→结果交付七个检查点。不能把 DataAgent 简化为「NL2SQL + 图表」。
- **一年建设路线（四季度 × 技术/治理/组织三线）**：Q1 Runtime/模型入口/工具注册/基础 trace/首个试点 + 工具风险等级与最小审批；Q2 评估/成本归集/审批接入/管理界面 + 评测样本模板与上线准入；Q3 语义层/RAG/第二业务线 + 口径权限 trace 规范；Q4 灰度/降级/SLO/供应商/平台目录 + 事故复盘/版本治理/合规。每阶段沉淀一种公共资产（统一任务状态模型、评测模板、语义层规范、平台目录）。
- **地图三用途**：项目映射（把现有试点标到四层与八簇，暴露缺口而非改名）；评审三结论（阶段结论：原型/试点/有限生产/平台目录；缺口结论：缺语义层/Runtime 状态/评估样本/HITL/Trace 等；责任结论：由哪个团队补）；协作契约（把产品/数据/平台/安全/业务语言转成同一组问题）。
- **建设顺序判断**：模型网关/工具注册/Trace/评测样本/权限边界是早期底座；Memory/多 Agent/DataAgent/Generative UI 在底座稳定后扩展；安全合规治理从第一天介入但先覆盖高风险链路。
- **常见误判**：把语义层缺失/工具契约混乱/审批边界不清归咎为「模型不够强」；把 trace 不统一/评测样本缺失归咎为「业务场景太复杂」。四层架构是定位这两类问题的共同语言。
