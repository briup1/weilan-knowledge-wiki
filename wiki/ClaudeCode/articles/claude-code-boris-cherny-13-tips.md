> Claude Code 之父 Boris Cherny 分享的 13 个高效使用技巧，结合实战经验详细解读，帮助你更高效地进行 Vibe Coding。

## 1. 尽可能并行

**原文**：在终端中同时运行 5 个 Claude 实例。将标签页编号为 1-5，并通过系统通知来获知哪个 Claude 需要输入指令。

**解读**：智能编程的能力已经比肩资深开发者，不需要像辅导实习生那样盯着它。运行更多实例、并行开发，能将工作效率最大化。唯一的缺点是 TOKEN 账单会上升。

## 2. 网页和本地同时并行

**原文**：同时在 http://claude.ai/code 上运行 5-10 个 Claude 实例，与本地 Claude 并行工作。在终端编程时，经常将本地会话转至网页端（使用 `&` 符号），或在 Chrome 中手动启动新会话，有时还会用 `--teleport` 参数在两端来回切换。每天早晨和白天工作中，会用手机（通过 Claude iOS 应用）开启几个会话，稍后再来查看进度。

**解读**：别把 Claude Code 只当成本地开发工具，多端并行能充分利用碎片时间。让智能编程软件在远程持续工作，把注意力放在更有价值的事情上。

## 3. 一个诸葛亮顶三个臭皮匠

**原文**：所有任务都使用支持深度思考的 Opus 4.5 模型。这是用过最好的编程模型——虽然比 Sonnet 版本更大、响应稍慢，但由于它几乎很少需要人工引导且具备更出色的工具调用能力，实际使用效率比小型模型更高。

**解读**：很多开发任务，使用贵的模型一次就能跑通；而使用免费或便宜的模型，可能卡在某个功能的实现上反复开发测试。在关键任务上，优先用最强模型。

## 4. 不要在同一个地方摔倒两次

**原文**：团队共享一个为 Claude Code 代码库设置的 `CLAUDE.md` 文件，并将其 check in 到 git 中，全体成员每周都会进行多次协作更新。每当发现 Claude 出现操作偏差，就会将其记录到 `CLAUDE.md` 中，这样 Claude 下次就能规避同样问题。其他团队也维护着各自的 `CLAUDE.md` 文件，及时更新内容已成为各团队的基本职责。

**解读**：开发经验对模型同样重要。`CLAUDE.md` 会作为上下文输入到智能体中，让它在开发时避免之前犯过的错误。持续迭代团队记忆是复利式工程。

## 5. 让模型学会我们的经验

**原文**：在代码审查时，经常在同事的 PR 中标记 `@.claude`，把需要补充到 `CLAUDE.md` 的内容作为 PR 的一部分。团队为此专门使用 Claude Code 的 GitHub Action（通过 `/install-github-action` 安装）。这相当于团队对 "复利式工程"（Compounding Engineering）的实践。

**解读**：智能编程有时像"抽卡"，是因为智能体没有认识到我们真正想要的是什么。将自己的真实需求尽可能详细地作为上下文给到智能体，才能持续提高输出质量。

## 6. 计划先行

**原文**：大多数会话都从规划模式开始（Plan mode，按两次 `shift+tab`）。如果目标是编写一份 Pull Request，就会使用规划模式，与 Claude 反复沟通直到对方案满意。随后切换到自动接受编辑模式（auto-accept edits mode），Claude 通常能一次搞定。一个优质的规划至关重要！

**解读**：以往的开发是渐进式的，但使用智能编程时，之前的代码会成为新功能的上下文约束。应该将更多时间花在计划上，完善产品需求文档。用人工智能对话帮助完善 PRD，最终产品在架构和功能实现上都会更优秀。

## 7. 将固定的工作打包成斜杠命令

**原文**：对于每天要重复多次的"内循环"（inner loop）工作流，全部使用斜杠命令实现。这让用户免于重复编写提示词，也让 Claude 能调用这些工作流。这些命令都通过 git 管理，存放在 `.claude/commands/` 目录中。例如，每天会使用几十次 `/commit-push-pr` 斜杠命令——该命令通过内联 bash 预计算 git 状态等信息实现快速执行，避免与模型来回沟通的耗时。

**解读**：之前一些固定的工作流使用脚本实现，现在可以让智能体帮我们实现和调用。把重复操作标准化为 slash command，能显著减少摩擦。

## 8. 将固定的工作打包成智能体

**原文**：经常使用几个子智能体：`code-simplifier` 在 Claude 完成任务后对代码进行简化，`verify-app` 包含端到端测试 Claude Code 的详细指令等。与斜杠命令类似，子智能体能自动化处理大多数 PR 执行的最常见工作流。

**解读**：使用子智能体代替我们完成一些常规的、固定的工作。把审查、简化、验证等任务交给专门的 subagent，是规模化使用 Claude Code 的关键。

## 9. 用 PostToolUse 钩子格式化代码

**原文**：团队用 PostToolUse 钩子函数格式化 Claude 生成的代码。Claude 通常能直接输出格式规范的代码，钩子会处理剩下的 10% 细节，避免后续 CI（持续集成）流程中出现格式错误。

**解读**：在工具调用链中插入自动化后处理，能消除最后的小问题，减少 CI 失败和人工修正。

## 10. 权限管理

**原文**：不使用 `--dangerously-skip-permissions` 参数，而是用 `/permissions` 命令预先授权环境中确认安全的常用 bash 命令，避免不必要的权限提示。这些设置大多保存在 `.claude/settings.json` 文件中并与团队共享。

**解读**：在安全和效率之间找到平衡。预先白名单化常用命令，既能减少打断，又不会完全放开权限。

## 11. 将 Claude Code 当成智能助理使用

**原文**：Claude Code 能调用所有工具：经常通过 MCP 服务器搜索并发布 Slack 消息、运行 BigQuery 查询分析数据（使用 `bq` 命令行工具）、从 Sentry 获取错误日志等。团队的 Slack MCP 配置已存入 `.mcp.json` 文件供团队共享使用。

**解读**：如果将 Claude Code 仅仅当成开发软件来用，显然没有完全发挥其用处。可以将其看成是通用的智能体，借助 SKILL 和 MCP，让它帮你处理更多的工作。

## 12. 长任务的技巧

**原文**：针对耗时较长的任务，会采取以下方式之一：

- (a) 要求 Claude 在完成后通过后台代理自行验证工作结果；
- (b) 使用一个代理 `Stop` 钩子，用更确定地方式执行验证；
- (c) 使用 ralph-wiggum 插件。

同时还会在沙箱环境中使用 `--permission-mode=dontAsk` 或 `--dangerously-skip-permissions` 参数，避免会话中的权限提示阻断 Claude 的连续工作流程。

**解读**：长任务最怕中途被打断。通过自动验证机制和降低权限摩擦，让 Claude 能够无人值守地完成长时间运行的工作。

## 13. 反馈的重要性

**原文**：要让 Claude Code 产出卓越成果，最关键的一点或许是——为 Claude 建立工作验证机制。当 Claude 拥有这种反馈循环时，最终结果的质量能提升 2-3 倍。

比如每次向 claude.ai/code 提交改动时，Claude 都会通过 Chrome 扩展进行全流程测试：自动打开浏览器、检测用户界面，持续迭代直到代码运行无误且用户体验流畅。

验证机制因领域而异——可能是简单的 bash 命令执行，或是完整的测试套件运行，或是浏览器/手机模拟器中的应用程序测试。请务必投入精力打造坚实可靠的验证体系。

**解读**：让智能体看见自己的开发输出结果很重要。这有助于其更好地定位问题和改进代码。验证闭环是高质量 AI 编程的放大器。

## 总结

Boris Cherny 的 13 个技巧可以归纳为几个核心主题：

1. **规模化并行**：多实例、多端、多 Agent 同时工作
2. **上下文投资**：持续维护 `CLAUDE.md`，让经验复利增长
3. **计划优于执行**：花更多时间在规划模式，减少返工
4. **自动化工作流**：用斜杠命令和子智能体封装重复任务
5. **验证闭环**：建立自动验证机制，让 AI 看到结果并自我修正
6. **超越编程**：把 Claude Code 当作通用智能助理，连接更多工具
