# 异步任务

异步任务是指将那些不需要立即返回结果、可能耗时较长的操作从主请求流程中剥离出来，交由独立的后台进程或工作节点执行的技术模式。

## 定义

在 Web 应用中，用户请求通常期望在数百毫秒内得到响应。然而，某些操作（如发送邮件、生成报表、处理图片、调用外部 API）可能需要数秒甚至更长时间。异步任务模式通过消息队列将这些操作投递到后台执行，主请求立即返回任务标识，客户端后续查询执行结果，从而避免阻塞用户交互。

## 核心原理

- **消息队列（Broker）**：任务以消息形式发送到队列（如 Redis、RabbitMQ），实现请求方与执行方的解耦。即使 Worker 暂时不可用，任务也不会丢失。
- **Worker 进程**：独立的进程池从队列中拉取任务并执行。Worker 数量可按负载横向扩展，与 Web 服务器进程互不影响。
- **结果后端（Backend）**：任务执行完毕后，结果存储在 Backend 中，客户端通过任务 ID 查询状态或获取结果。
- **任务幂等性**：设计任务时保证多次执行结果一致，配合重试机制可优雅处理临时故障。

## Celery 架构

Celery 是 Python 生态中最成熟的异步任务框架，其核心架构包含：

- **Producer**：在 FastAPI 路由中调用 `.delay()` 或 `.apply_async()` 发送任务。
- **Broker**：接收并暂存任务消息，常用 Redis（配置简单）或 RabbitMQ（功能完善）。
- **Worker**：从 Broker 消费消息并执行任务，支持并发模式（prefork、eventlet、gevent）。
- **Beat**：定时任务调度器，按预设周期将任务投递到队列，替代传统 crontab。

## 适用场景

- **发送邮件/短信**：邮件服务响应慢且不稳定，异步发送可避免阻塞用户注册流程。
- **数据处理与 ETL**：批量导入、数据清洗、报表生成等耗时计算。
- **图片/视频处理**：缩略图生成、格式转换、视频切片等多媒体处理任务。
- **第三方 API 调用**：支付回调、物流查询、社交媒体发布等外部依赖操作。
- **定时任务**：每日数据备份、定期统计报表、缓存预热等周期性工作。

## 与 Agent 编排的关系

在 Agent 系统里，异步任务不仅仅是后台执行，还涉及 **事件驱动的异步 Agent 架构**：

- Agent 需要管理长时间运行的工具调用，不被同步等待阻塞。
- 外部事件（邮件、日历、系统告警、第三方回调）可能随时打断当前任务。
- 需要事件队列 + 优先级策略：取消式（紧急）、队列式（常规）、并行式（独立轻量查询）。

这与 [[orchestration-loop]] 的 ReAct 循环形成张力：LLM 训练范式假设同步序列（tool call → tool result），而真实部署需要异步打断与恢复。当前工程上常用占位符、异步工具接口（`initiate_*` / `on_*_event`）和事件状态栏来缓解。
