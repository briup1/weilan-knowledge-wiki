# Agent 任务 SLO

Agent 任务 SLO 是对“用户能否在可接受的时间和成本内完成有质量的任务”的可度量目标。它不把单次 HTTP 是否返回 200 当成任务成功。

## 先拆开再写数

不同场景的等待不一样：对话要首响应，报表要最终完成，写操作还要看有没有越权和能不能恢复。至少分开看首响应、最终完成、任务成功、质量、安全、成本和恢复。

SLI 是测到的数，SLO 是内部目标，SLA 是对外承诺。目标和护栏分开写。延迟按链路阶段拆，成功率按层次算。看板上的一个汇总数不能直接当发布门禁。

错误预算把“还能不能发”从感觉变成规则。Agent 的预算不只扣可用性，也扣质量、成本和风险。

## 三道防线

| 动作 | 保护什么 | 不能做什么 |
|---|---|---|
| 限流 | 入口量和公平性 | 不能只限住后来的请求，却让已进入的写操作失去审计 |
| 熔断 | 不健康的下游 | 不能把失败伪装成任务成功 |
| 降级 | 一条仍可完成或可解释的替代路径 | 不能绕过权限、脱敏、审批和审计 |

长任务和单次 HTTP 生命周期解开，恢复靠 [[agent-run-lifecycle]] 的状态机、检查点和幂等键，等待靠 [[human-in-the-loop]]。容量要算步骤放大、重试放大、缓存命中和评测抽样，不能用入口 QPS 直接当模型调用量。

具体数字必须按场景另定。本章方法没有给出可照抄的阈值。
