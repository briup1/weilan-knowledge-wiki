# 负载测试

负载测试（Load Testing）是一种通过模拟大量并发用户访问，评估系统在预期负载下的性能表现、稳定性和瓶颈位置的测试方法。它是保障应用上线后能够承受真实流量的关键工程实践。

## 定义

负载测试的核心目标不是证明系统"能跑"，而是量化系统在特定并发量下的响应能力，提前暴露瓶颈（CPU、数据库连接、内存、网络带宽等），为优化决策提供数据依据。它与压力测试（Stress Testing）略有不同：负载测试关注预期负载下的表现，而压力测试关注系统在极限负载甚至崩溃边缘的行为。

## 核心原理

- **并发模拟**：同时发起大量请求，模拟真实世界中多个用户同时操作系统的场景。
- **指标采集**：持续记录响应时间、吞吐量（RPS/QPS）、错误率、CPU 和内存占用等关键指标。
- **瓶颈定位**：通过逐步增加负载，观察哪个指标最先达到极限，从而定位系统短板。
- **基线建立**：每次大版本更新或架构调整后重新压测，与历史基线对比，防止性能退化。

## Locust 工具

Locust 是 Python 生态中广受欢迎的负载测试工具，其核心特点包括：

- **纯 Python 脚本**：使用普通 Python 代码定义用户行为，无需学习专用 DSL。
- **真实用户模拟**：继承 `HttpUser`，设置 `wait_time = between(1, 3)` 模拟用户思考时间，用 `@task` 装饰器定义行为权重。
- **Web UI 实时监控**：启动后自动提供 Web 界面，展示 RPS、响应时间分布、失败率等实时图表。
- **分布式施压**：支持多机分布式模式，突破单机压测客户端自身成为瓶颈的限制。

## 关键性能指标

- **RPS（Requests Per Second）**：每秒处理请求数，衡量系统吞吐能力。
- **响应时间（Response Time）**：从发送请求到收到响应的时间，通常关注 P50、P95、P99 分位数。
- **错误率（Error Rate）**：失败请求占比，超过阈值通常意味着系统已超负荷。
- **并发用户数**：同时在线并执行操作的用户数量，是压测的主要控制变量。

## 适用场景

- **上线前验证**：在正式发布前确认系统能承受预期峰值流量。
- **架构选型对比**：对比不同技术方案（如同步 vs 异步、单进程 vs 多进程）的性能差异。
- **优化效果验证**：实施缓存、连接池、多进程等优化后，通过压测量化改进幅度。
- **容量规划**：根据压测结果推算系统在不同硬件配置下的承载能力，指导扩容决策。

## 最佳实践

- **不要在生产环境直接压测**：应在与生产环境一致的 staging 环境进行，避免影响真实用户。
- **调整系统限制**：Linux 默认文件句柄数 1024，高并发下需提前修改 `/etc/security/limits.conf`。
- **避免客户端瓶颈**：单机压测时注意客户端 CPU 和网络是否先达到上限，必要时使用 Locust 分布式模式。
- **压测常态化**：每次大版本更新或架构调整都应重新压测，建立性能回归机制。
