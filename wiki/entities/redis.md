# Redis

Redis 是一个开源的内存数据结构存储系统，可用作数据库、缓存和消息代理。它以极高的读写性能和丰富的数据结构支持，成为现代 Web 应用架构中不可或缺的基础设施组件。

## 核心组件与特性

- **内存存储与高性能**：数据主要保存在内存中，读写延迟在微秒级，远快于传统磁盘数据库，非常适合高并发场景。
- **丰富的数据结构**：支持字符串、哈希、列表、集合、有序集合、Bitmap、HyperLogLog、流（Stream）等多种数据类型，满足不同业务需求。
- **缓存层**：作为热点数据缓存，可显著降低数据库压力。合理设置过期时间（TTL）是缓存设计的核心。
- **消息队列**：利用列表（List）的 LPUSH/BRPOP 或发布/订阅（Pub/Sub）实现轻量级消息传递；在 Celery 中则作为 Broker 和 Backend 使用。
- **持久化**：支持 RDB（快照）和 AOF（追加日志）两种持久化方式，可在性能与数据安全之间权衡选择。
- **分布式锁与计数器**：原子操作支持高并发下的资源竞争控制，如限流、库存扣减等场景。

## 使用指南与最佳实践

- **连接池管理**：在生产环境中使用连接池复用连接，避免频繁创建和销毁带来的开销。在 Celery 任务中通过上下文管理器获取和归还连接。
- **缓存策略**：对读取频繁但更新不频繁的数据（如用户配置、商品详情）优先加缓存；写操作后及时失效或更新缓存，防止脏读。
- **作为 Celery Broker**：配置简单，性能足够支撑大多数中小型项目；大规模场景可考虑 RabbitMQ 以获得更完善的消息确认和路由能力。
- **作为 fastapi-users 令牌存储**：使用 RedisStrategy 存储认证令牌，兼具高性能和服务端可控性（登出时可删除令牌）；详见 [[fastapi-users-auth-transport-strategy-2]]。
- **数据持久化**：生产环境建议同时开启 RDB 和 AOF，并配置合理的备份策略，防止内存数据丢失。
