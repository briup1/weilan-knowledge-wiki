# Agent 上下文分享设计文档

## 1. 目标

为团队后端/全栈工程师提供一次 45–60 分钟的技术分享，帮助他们建立 Agent 上下文的系统认知，并意识到上下文压缩与记忆设计在实际工程中的价值。

## 2. 听众

- 有后端/全栈开发经验
- 没有直接做过 Agent 项目
- 对 LLM 有基础了解（prompt、tool use 概念）

## 3. 成功标准

1. 听众能画出一次 Agent 推理的「上下文剖面图」。
2. 听众认同上下文是有限资源，压缩与记忆设计值得投入。
3. 听众能带走一个可在团队当前/即将开展的 Agent 功能中验证的改进点。

## 4. 叙事主线

**X-Ray 透视法**

先展示 Agent 一次推理时上下文窗口里的真实构成，再逐层讲解可以如何优化，最后把记忆系统作为「窗口外的长期上下文」收束。

## 5. 分享结构

| Section | 内容 | 时长 |
|---|---|---|
| 开场钩子 | 用「Agent 突然变傻」的真实感故事引出上下文爆炸问题 | 5 min |
| 上下文剖面图 | 四层模型：静态前缀、轨迹、动态提示词、状态栏 | 12–15 min |
| 静态前缀优化 | System Prompt 与 Skill/Tool Prompt 设计原则 | 10 min |
| 轨迹与工具输出压缩 | 轨迹膨胀原因、压缩对象/时机/方式、大工具返回处理 | 12 min |
| 记忆设计 | 工作记忆、episodic 记忆、语义记忆的分层 | 8–10 min |
| 落地 CTA | 回到团队项目，给出 2 周内可验证的压缩实验 | 5 min |

**总时长：50–57 分钟**，预留 3–5 分钟弹性。

## 7. 深度控制

- **不讲**：KV Cache 实现细节、复杂工具匹配算法、多 Agent 协作。
- **点到为止**：`turn / trace` 概念、KV Cache 作为可选进阶方向。
- **重点展开**：上下文剖面图、System/Tool Prompt 设计、工具输出压缩、记忆分层。

## 8. 落地 CTA 模板

留给听众一个可带走的检查清单：

1. 选出团队当前/ upcoming 的一个 Agent 功能。
2. 用四层模型画出它的上下文剖面。
3. 找出最大的 token 消耗项。
4. 设计一个 2 周内可验证的压缩或记忆化实验。
5. 记录基线指标（token 数、延迟、准确率）与实验结果。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 听众对 Agent 没概念，跟不上 | 开场先给最小必要背景，所有例子用后端/全栈熟悉的接口调用类比 |
| 内容变成技巧清单，缺统一模型 | 全程用「四层剖面图」作为锚点，每个技巧都说明它作用于哪一层 |
| 时间超支 | Section 2 和 Section 4 准备可裁剪版本；必要时跳过状态栏细节 |
| 结尾没有行动 | 必须留出 5 分钟，给出具体 CTA 模板 |
